# Google Диск: база между обновлениями хостинга

Бот работает с локальной SQLite. Google Диск хранит проверенные ZIP-копии:
базу пользователей, карточек, настроек и черновиков, загруженные картинки и
пользовательские шрифты. Токен бота, OAuth-секреты, .env и код в архив не попадают.

## Одна переменная окружения

В настройках хостинга добавь `INFOBOX_GOOGLE_DRIVE`. Значение - JSON в одну строку:

```json
{"folder_id":"ID_ПАПКИ","client_id":"OAUTH_CLIENT_ID","client_secret":"OAUTH_CLIENT_SECRET","refresh_token":"OAUTH_REFRESH_TOKEN","interval":30,"keep":5,"initialize_empty":false}
```

Это секретная настройка хостинга. Не публикуй значение в GitHub и не присылай
refresh_token в общий чат. Одной ссылки на папку недостаточно для записи.

- `folder_id` - часть ссылки после `/folders/`, без ссылки целиком
- `client_id`, `client_secret`, `refresh_token` - OAuth-доступ владельца папки
- `interval` - проверка изменений каждые 30 секунд, допустимо 10-3600
- `keep` - последние 5 завершенных копий, допустимо 2-30
- `initialize_empty` - разрешить создание базы, когда нет ни локальной базы,
  ни копии на Диске. Обычно `false`

## Получить доступ один раз

1. В Google Cloud Console создай проект и включи Google Drive API
2. Настрой OAuth consent screen для своего аккаунта и создай OAuth client типа
   Web application. Для настройки через OAuth Playground добавь redirect URI
   `https://developers.google.com/oauthplayground`
3. Открой [OAuth Playground](https://developers.google.com/oauthplayground),
   в настройках включи `Use your own OAuth credentials` и укажи свой client ID
   и client secret
4. Авторизуй свой аккаунт со scope `https://www.googleapis.com/auth/drive`,
   обменяй authorization code на токены. Нужен именно `refresh_token` для
   offline access, короткоживущий `access_token` в env не подходит
5. Создай отдельную закрытую папку в своем Google Диске и возьми ее ID
6. Собери JSON выше в переменной окружения хостинга и перезапусти бота

Бот сам обновляет access token через Google OAuth. Отзыв доступа или истечение
refresh_token потребует нового подключения. У OAuth-приложений в режиме Testing
есть ограничения срока refresh_token: для постоянной работы проверь статус
consent screen и правила Google для выбранного типа приложения.

Источники: [OAuth offline access](https://developers.google.com/identity/protocols/oauth2/web-server#offline),
[поиск файлов](https://developers.google.com/workspace/drive/api/guides/search-files),
[загрузка файлов](https://developers.google.com/workspace/drive/api/guides/manage-uploads).

## Что происходит при запуске

- Нет env: админ получает предупреждение, что Диск не подключен. Бот использует
  прежнюю локальную базу без облачных копий
- Есть env: админ получает редактируемое сообщение с этапами подключения,
  поиска копии, скачивания с реальным счетчиком КБ и восстановления
- Локальная база существует: бот проверяет ее и сохраняет, не заменяет более
  старой облачной копией
- Локальной базы нет: скачивается последняя завершенная копия. Проверяются
  контрольные суммы файлов и целостность SQLite. Сначала восстанавливаются
  картинки и шрифты, затем атомарно публикуется база
- Нет ни базы, ни облачной копии: запуск останавливается. Для действительно
  нового бота можно один раз поставить `initialize_empty:true`. После первой
  успешной копии верни `false`, чтобы пустая папка не стала разрешением на сброс
- Ошибка настроенного Диска, архива или первой выгрузки: админ получает ошибку,
  обычная работа не начинается. Существующая копия не перезаписывается
- Перед приемом пользователей создается первая проверенная копия. Как и раньше,
  техработы остаются включены до `/maint_off`

Админом считается основной аккаунт из `admin.py` и аккаунты из `ADMIN_IDS`.
Чтобы получать личные сообщения, админ должен хотя бы один раз открыть бота
и нажать Start. Если Telegram блокирует доставку, ошибка отражается в логах,
восстановление от этого не прерывается.

## Сохранение во время работы

Каждые `interval` секунд бот проверяет изменения базы, WAL, картинок и шрифтов.
При изменениях создает согласованный снимок через SQLite backup API и загружает
новый архив. Предыдущие архивы не перезаписываются. После подтверждения Google
лишние старые копии перемещаются в корзину. Другие файлы папки не затрагиваются.

При ошибке админ получает предупреждение, повторные попытки продолжаются.
При восстановлении связи приходит сообщение об успешном сохранении.
При штатной остановке выполняется финальная выгрузка. Если хостинг мгновенно
убил процесс или стер диск до выгрузки, восстановятся данные последней
успешной копии. Абсолютно нулевую потерю последних изменений эта схема не дает.

Один набор базы и папка предназначены для одного работающего экземпляра бота.
Не запускай одновременно два хостинга, записывающих разные базы в эту папку.
Перед плановым обновлением останови бота штатно и дождись сообщения о сохранении.

Резервные копии содержат пользовательские данные: папка должна оставаться
закрытой. Копии не шифруются отдельно от хранения в Google Диске.
